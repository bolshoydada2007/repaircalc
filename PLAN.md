Часть 1. План развития RepairCalc: от хакатона к продукту

Стадия 0 — что уже есть (не переписывать). FastAPI + SQLite, формулы расхода (плитка, покраска, обои с раппортом, ламинат), 44 pytest-теста, скоринг (цена 0.5 + рейтинг 0.35 + наличие 0.15), демо-страница с расчётом сметы и подбором по фото через цветовой профиль, README и журнал STEPLOG.md.



Стадия 1. Реальные данные (недели 1–3)

Подключить каталог магазина: официальный API по договорённости (после хакатона организаторы часто дают доступ участникам) или публичный прайс.

Фоновая синхронизация цен и наличия хотя бы раз в сутки (cron/планировщик).

Когда появятся изображения товаров — заменить цветовые эталоны на эмбеддинги фото (сигнатура match\_products уже готова).

Критерий готовности: смета формируется из актуальных цен, которые пользователь может проверить на сайте магазина.

Стадия 2. Пользовательская ценность (недели 3–6)

Telegram-бот: сохранение смет, история, повторный расчёт.

Экспорт сметы в PDF со ссылками на товары — главный вирусный артефакт: им делятся в чатах с мастерами и семьёй.

Сравнение цен между категориями/альтернативами: «замени плитку — сэкономишь 4 300 ₽».

Критерий готовности: пользователь возвращается к сохранённой смете без повторного ввода данных.

Стадия 3. Монетизация (недели 6–8, выбор одной модели)

Партнёрская программа магазина (приоритет): комиссия за переход/покупку по ссылкам из сметы. Нужен договор или хотя бы официальный partnership.

B2B-тариф для мастеров и дизайнеров: безлимит смет, брендированный PDF, несколько объектов.

API-подписка для агрегаторов и застройщиков.

Критерий готовности: первая тысяча рублей заработанных или подписанный Letter of Intent с магазином.

Стадия 4. Техническая зрелость (параллельно)

PostgreSQL + миграции (Alembic) вместо SQLite.

Деплой на VPS/облако с HTTPS и доменом.

Rate-limit на эндпоинт фото, логирование, резервное копирование базы.

Аналитика событий (постраничные просмотры, расчёты, клики «в магазин») — без неё не продать партнёрство.

Стадия 5. Юридика и позиционирование

Политика обработки персональных данных, пользовательское соглашение.

Бренды магазинов упоминать корректно: либо договор с магазином, либо позиционирование «агрегатор стройматериалов» без чужого бренда в названии продукта.

Порядок жёсткий: данные → ценность → деньги. Не строить фичи до работающей трубы реальных данных.
